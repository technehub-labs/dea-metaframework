# ECF Architectural Position

Status: Normative (CR-ECF-001)
Scope: `technehub-labs/dea-metaframework` and downstream ECF consumers

## 1. Position in the Semantic and OpenDEA Architecture

The Enterprise Concept Framework (ECF) is an enterprise organizing framework
within OpenDEA. It is not the foundational ontology of the enterprise or the
world.

```
World Semantic Foundation (WSF)
        foundational semantics
                |
                v
OpenDEA Core Semantics
        WSF specialized for enterprise architecture
                |
    +-----------+------------+-----------+
    |           |            |           |
ECF Profile   Business     Data       Technology
(this repo)   Profile      Profile    Profile
    |
    v
ECF Coordinates (Domain x Stage; 7 x 7 = 49)
    |
    |           +----------- other OpenDEA Profiles
    v           v
OpenDEA Metamodel
        formal semantic representation
                |
                v
Reference Catalogs
        governed concept instances
```

WSF provides foundational semantic grounding. OpenDEA specializes that
grounding for enterprise architecture while remaining independently governed.
ECF provides the enterprise domain/lifecycle organizing framework within
OpenDEA.

## 2. Architectural Boundary

The following distinctions are normative:

```
WSF  !=  OpenDEA  !=  ECF  !=  DEA Metamodel  !=  Catalog
```

and:

```
ECF
    organizes and contextualizes
        |
        v
OpenDEA Metamodel
    formally represents
        |
        v
Catalogs
    instantiate governed concepts
```

No ECF artifact claims authority over WSF semantics. No artifact in this
repository redefines the OpenDEA metamodel; the metamodel remains the
canonical semantic model.

## 3. OpenDEA Profile Architecture

The live `dea-metamodel` implements a core/profile architecture: Core
contains stable semantic anchors; profiles extend Core without redefining it.
ECF is one such profile. This repository defines the ECF framework and
coordinate contract; `dea-metamodel` owns the formal semantic representation
of ECF constructs. No competing ECF entity model is created here.

## 4. Downstream Contract

The following downstream interpretation is the ECF contract:

- **Business Capability**: ECF coordinates are classification context, not
  capability identity. Capability identity remains independent of ECF
  coordinate. The ECF does not manufacture capabilities.
- **Business Process**: an ECF intersection establishes Process Context; it
  does not itself constitute a Business Process.
- **Metamodel**: the metamodel remains the canonical semantic model. Its
  normative specification is the source from which schemas and other
  representations are derived.

No catalog is generated by enumerating ECF coordinates. A coordinate
establishes a context; a consuming catalog determines whether zero, one, or
many modeled elements are appropriate within that context.

## 5. Downstream Consumers

The following repositories are consumers of the ECF contract:

| Repository | Consumption |
|------------|-------------|
| `technehub-labs/dea-metamodel` | ECF profile: formal representation of Domain, Stage, Coordinate |
| `technehub-labs/dea-catalog-business-capabilities` | Capability classification context |
| `technehub-labs/dea-catalog-processes` | Process Context for Business Process Architecture |

Further `dea-catalog-*` repositories declare ECF consumption through governed
OpenDEA mechanisms as they adopt the coordinate contract.
